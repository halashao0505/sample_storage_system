# 07 DB 与 JSON 读取扩展规划

## 1. 当前已知范围

目前只确定平台后期需要读取两类外部数据：

1. SQLite `.db` 文件；
2. `.json` 文件。

它们将来包含什么表、字段、层级、编码和业务含义尚未确定。因此当前阶段只规划稳定的读取边界，不编写字段映射、导入规则、同步逻辑或写回能力。

## 2. 当前不做的假设

- 不假设 `.db` 中一定有哪些表或列；
- 不假设 JSON 是对象、数组或固定字段；
- 不根据当前其它项目中的同名文件推断本平台格式；
- 不预设数据属于样品、任务、状态、参数还是测试结果；
- 不承诺持续同步、一次导入或双向写回；
- 不把 JSON 设计成平台事务主库。

只有拿到真实样例、生产方和更新方式后，才确定每一个来源的实际用途。

## 3. 预留模块边界

```text
backend/app/integrations/data_readers/
├─ contract.py                 # 统一读取结果和错误模型
├─ registry.py                 # 按已配置 source_type 选择读取器
├─ sqlite_reader.py            # 后期实现 SQLite 只读访问
├─ json_reader.py              # 后期实现 JSON 读取
└─ mappings/                   # 拿到真实结构后按来源版本添加
```

`samples/tasks/runs` 等业务模块不能直接打开 `.db` 或 `.json`。它们只接收读取器转换后的标准候选数据。

## 4. 统一读取器契约

两个读取器未来至少提供相同的外层结果：

```text
source_id                  来源标识
source_type                sqlite | json
source_version             来源格式版本，未知时为空
read_at                    本次读取时间
fingerprint                文件或数据快照指纹
records                    尚未映射的原始记录集合
warnings                   可继续处理的警告
errors                     无法处理的错误
metadata                   文件大小、修改时间等来源信息
```

这里的 `records` 只是兼容层输出，不直接等于平台样品。拿到真实样例后，再增加该来源专用 mapper：

```text
Reader → RawRecord → SourceMapper → Sample/Task/Run/File Candidate
```

## 5. SQLite Reader 后期职责

拿到真实 `.db` 后再确定：

- SQLite 文件版本和实际 schema；
- 允许读取的表、列和查询；
- 是否由另一个程序同时写入；
- 需要一次导入还是周期读取；
- 记录的稳定身份字段；
- 锁、超时和一致性快照策略。

读取器默认使用只读连接，不在验证阶段写真实 DB。

## 6. JSON Reader 后期职责

拿到真实 JSON 后再确定：

- UTF-8、BOM 或其它编码；
- 根节点是 object 还是 array；
- 必填字段和允许的空值；
- schema version 如何表示；
- 文件是否会被运行程序覆盖更新；
- 单条数据的稳定身份字段；
- 一次导入、周期读取或文件监听方式。

读取失败只能标记该来源异常，不能清空平台已有样品或历史记录。

## 7. 拿到真实样例后的固定步骤

```text
复制一份脱敏样例
  → 确认文件生产者和更新时间
  → 只读检查结构、编码和容量
  → 定义 source schema v1
  → 明确字段业务含义
  → 定义到平台模型的 mapping
  → 编写 reader + mapper
  → 使用样例做精确回归测试
  → 在副本环境验证
  → 最后决定是否接入真实目录
```

如果同为 `.db` 或 `.json` 但结构不同，每个来源使用独立 mapper 和版本，不在一个函数里堆大量文件名判断。

## 8. 与平台主库的关系

- 平台业务主库首版仍使用 SQLite；
- 外部 `.db` 是数据来源，不自动成为平台主库；
- 外部 JSON 是数据交换/读取来源，不承担事务一致性；
- 是否需要导出 DB/JSON，等真实调用方提出明确契约后再规划；
- 不建立两个可写主库，避免样品状态冲突。

## 9. 验收要求

实现具体读取器时至少验证：

1. 真实来源文件在读取前后没有被修改；
2. 缺字段、未知字段、空文件和损坏文件有明确错误；
3. 重复读取不会重复创建业务数据；
4. 读取一个来源失败不影响 XAFS、XRD 和其它来源；
5. 原始内容、标准化内容和平台实体之间可以追溯；
6. 离线检查与真实运行目录验证分开记录。
