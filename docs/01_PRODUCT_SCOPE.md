# 01 产品范围与总体大纲

## 1. 产品定位

平台的核心问题不是“数据库里有多少条样品记录”，而是让实验室人员随时回答：

- 今天提交、排队、测试和完成了多少样品？
- 当前设备正在测试哪个样品，进度是否可信，预计何时结束？
- 后续有哪些任务，每个送样人预计等待多久？
- 某个样品由谁提交、谁安排、谁测试、使用什么参数、产生哪些文件？
- 某段时间的测试量、平均等待时间、成功率和设备利用率如何？

产品名称暂定为 **ZJUT Sample Platform / 多谱仪样品测试运营平台**。首批纳管 XAFS 和 XRD，但公共样品、任务、排队、执行、文件和统计模型不绑定某一种谱仪。

## 2. 用户角色

| 角色 | 主要目标 | 首版权限 |
| --- | --- | --- |
| 管理员 | 管理用户、设备、测试类型和系统配置 | 全部管理功能；无网页危险设备控制 |
| 实验员 | 排队、确认任务、关联测试结果、处理异常 | 样品和测试业务操作 |
| 送样用户 | 提交和查看自己的样品进度、结果 | 仅本人/本课题组范围 |
| 访客/大屏 | 查看经过脱敏的运行概览 | 只读概览，可后续启用 |

首版先完成管理员和实验员流程。送样用户自助入口在核心流程稳定后开放。

## 3. 核心业务对象

### Sample（样品）

描述样品本身：平台编号、外部编号、名称、申请人、课题组、材料类别、危险说明、备注和创建时间。

### Test Task（测试任务）

描述“准备做的一次测试”：技术类型（XAFS/XRD）、测试类型、参数快照、预计耗时、优先级、队列位置、计划设备和任务状态。同一个样品可以先做 XRD，再做 XAFS；它们是两个任务而不是两个样品。

### Test Run（实际测试）

描述设备真正执行的一次过程：真实开始/结束时间、操作员、设备、执行结果、异常原因、进度快照和结果摘要。

### Test Event（生命周期事件）

记录每次状态变化，事件只能追加不能覆盖，用于还原完整时间线。

### Attachment（附件/结果文件）

记录原始数据、导出数据、图片和报告；文件内容与结构化业务记录分离。

必须坚持：**样品数量不等于测试次数**。一个样品允许重复测试或使用不同测试类型。

## 4. 统一状态

```text
draft → pending → queued → testing → completed
                            ├──────→ paused → testing
                            └──────→ failed
pending / queued ─────────────────→ cancelled
```

| 状态 | 中文 | 含义 |
| --- | --- | --- |
| `draft` | 草稿 | 信息尚未提交 |
| `pending` | 待处理 | 已提交，实验员尚未确认排队 |
| `queued` | 排队中 | 已进入设备队列 |
| `testing` | 测试中 | 已收到可信的实际开始事件 |
| `paused` | 已暂停 | 控制程序明确报告暂停，不靠网页猜测 |
| `completed` | 已完成 | 执行结束且必要结果已登记 |
| `failed` | 失败 | 执行失败，保留错误和已产生的数据 |
| `cancelled` | 已取消 | 未完成且不再执行 |

前端只显示中文，API 和数据库统一保存英文枚举值。

## 5. 页面范围

### Overview

- 今日样品、完成数、测试次数、累计测试时间、待测试数量；
- 支持“全部 / XAFS / XRD / 具体设备”范围切换，默认展示全部谱仪汇总；
- 样品数/测试次数/测试时长/完成率趋势；
- XAFS、XRD 各自的当前测试样品及状态更新时间；
- 各设备队列前几项及预计开始时间；
- 最近测试记录和异常提醒。

### Queue

- 待处理与排队任务；
- 拖动排序、优先级、计划设备、预计耗时；
- 预计开始/完成时间；
- 每次人工调整写入审计记录。

队列按设备独立维护，禁止把 XAFS 与 XRD 任务排进一条无法执行的混合设备队列。总览可以并列展示多条队列。

首版调度算法只做可解释的顺序累计，不做黑盒智能调度。

### Samples

- 搜索、组合筛选、分页和保存视图；
- 右侧抽屉快速查看样品；
- 完整详情页展示基本信息、全部任务、生命周期、文件和备注。

### History

- 以实际测试记录为中心；
- 显示真实参数快照、起止时间、设备、操作员、结果、异常和文件；
- 支持按日期、状态、测试类型、用户、课题组和设备筛选。
- 结果摘要按技术类型展示：XAFS 使用能量/角度、ROI 等字段；XRD 使用 2Theta、步长、曝光和衍射曲线字段。

### Analytics

- 日/周/月/年/自定义范围；
- 测试量、测试次数、测试时长、平均等待、成功率、设备利用率；
- 按测试类型、课题组、设备等维度拆分。

### Settings

- 用户和角色；
- 课题组；
- 设备；
- 测试类型和默认预计耗时；
- 文件存储、备份和系统参数。

## 6. 首页判断逻辑

首页按设备显示“当前测试”，同一时刻可以同时存在 XAFS 和 XRD 当前样品。每张卡只能来自带任务身份和时间戳的可信执行状态。不得因为某个线程存在、某个全局变量未清空或某个文件刚更新就猜测样品正在测试。

首页进度优先级：

1. 控制程序提供 `completed_points / total_points`；
2. 有明确分段任务时按各段点数计算；
3. 没有真实进度时只显示“测试中”和已运行时间，不显示伪造百分比。

技术专属字段不能强行共用：

- XAFS 卡片可显示当前 energy/theta、completed points、ROI；
- XRD 卡片可显示当前 2Theta、扫描点、曝光时间和样品工位；
- 公共卡片层只认样品、任务、设备、状态、进度和时间。

预计完成时间由当前执行的剩余点数和真实平均点耗时估算，界面必须标注“预计”。

## 7. 明确不做

- 网页远程启动高压、打开快门、移动轴或执行急停；
- 首版微服务、消息队列、Kubernetes、多租户；
- 把所有原始测试点写成首页查询表；
- 自动删除历史文件；
- 未经现场确认就宣称设备状态或执行结果可靠；
- 为尚不存在的测试文件格式提前编写解析器。
- 让 XAFS 或 XRD 的设备专属参数进入公共 sample 表。
- 把现有 DB、JSON 和平台数据库同时作为可写业务真相。

## 8. 首版完成标准

首版应形成一个闭环：

```text
登记样品 → 创建任务 → 排队 → 关联一次真实/模拟执行
→ 完成或失败 → 登记结果文件 → 样品详情可追溯 → 首页和统计同步更新
```

闭环内的每个状态变化都有操作者、来源、时间和审计记录。
