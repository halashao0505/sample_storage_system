# 06 实施路线图与验收标准

## 阶段 0：规划确认

交付：

- 产品范围；
- 技术架构与目录；
- 数据模型；
- XAFS/XRD 接入契约；
- DB/JSON 读取器扩展边界；具体结构待真实样例确定；
- 页面体系和视觉规范；
- 1920 × 1080 首页效果图。

确认项：平台名称、首批角色、样品编号规则、局域网访问范围、首页需要展示的两类谱仪字段。DB/JSON 字段不在本阶段猜测。

未确认前不批量生成代码。

## 阶段 1：工程骨架和设计系统

后端：

- FastAPI 启动、配置、日志、健康检查；
- SQLAlchemy/Alembic 基础；
- 测试数据库和基础检查。

前端：

- Vue/TypeScript/Vite；
- 路由、主布局、tokens、Button/Card/Table/StatusTag/Drawer；
- Overview 静态数据版；
- 1440/1920 和窄屏基础适配。

验收：一条命令分别启动前后端；构建无错误；首页样式与确认效果图一致。

## 阶段 2：样品、任务和队列闭环

- users/research_groups/samples/test_types/test_tasks/queue_entries；
- 样品登记、搜索、详情；
- 创建 XAFS/XRD 任务、按设备入队、排序、取消；
- 状态机、版本冲突和审计；
- 可解释的预计开始/完成时间。

验收：两个用户并发调整队列时不静默覆盖；样品和测试次数统计严格区分。

## 阶段 3：执行记录和文件

- test_runs/test_events/attachments；
- 手工关联一次执行；
- 使用平台定义的模拟结果完成文件生命周期；
- 原始文件校验、规范结果、CSV/曲线预览；
- History、Timeline、Files 页面。

验收：同一样品两次测试互不覆盖；空保存路径/无附件不终止业务流程；解析失败仍保留原文件和错误。

## 阶段 4：DB/JSON 读取器（拿到真实样例后）

- 对真实脱敏样例确认 SQLite schema 或 JSON 结构；
- 明确来源属于样品、任务、状态、配置还是结果；
- 为每个来源建立 schema version、reader 和 mapper；
- 先在副本环境验证只读、错误、重复读取和追溯；
- 再决定一次导入、周期读取或暂不接入。

验收：读取前后来源文件不变；损坏/变化数据有明确错误；重复读取不重复创建业务数据。

## 阶段 5：XAFS/XRD 只读接入

- 两套控制程序分别增加带身份的统一只读平台快照；
- XAFS/XRD collector 独立处理协议、超时、重连、幂等和来源实例识别；
- 多设备当前样品、进度、结果登记和断线语义；
- XRD 设备 sample_id 与平台 task/run/sample ID 的稳定映射；
- SSE 推送到网页。

验收分两部分：

1. 假服务：分包/粘包、超时、重复事件、断线重连全部通过；
2. 现场：分别对 XAFS 与 XRD 核对任务身份、进度、完成时间、结果点和文件；一台谱仪离线不影响另一台。

## 阶段 6：统计、权限与部署

- Analytics 指标定义和查询；
- 管理员/实验员/送样用户权限；
- Windows 服务、局域网访问、TLS/反向代理（如需要）；
- 自动备份、恢复演练、日志轮转和运行说明。

验收：权限越界测试、备份恢复、断电/重启恢复、错误提示和审计记录通过。

## 测试矩阵

| 风险 | 最小自动检查 | 现场检查 |
| --- | --- | --- |
| 状态错误 | 状态机表驱动测试 | 实际开始/暂停/完成 |
| 样品串数据 | 两样品交错执行测试 | 连续两次真实任务 |
| 重复事件 | 同 source_event_id 重放 | 控制程序重连 |
| 队列覆盖 | version 冲突测试 | 两浏览器同时调整 |
| 文件串样 | run_id 路径和 hash 测试 | 实际结果目录核对 |
| DB/JSON 读取错误 | 拿到样例后定义 | 副本验证后再读真实来源 |
| 多谱仪隔离 | 一个 fake source 故障 | 关闭其中一套控制程序 |
| 断线误判 | testing 后断线测试 | 拔线/关闭来源程序 |
| 协议分帧 | 拆包、粘包、超长帧 | 局域网稳定性观察 |
| 统计口径 | 固定数据集断言 | 月报抽样核对 |

## 代码审查门槛

- 新功能明确属于哪个模块；
- API、Service、Repository 与 Integration 不越层；
- 危险设备边界没有被网页绕过；
- 任务、run、sample 身份贯穿完整；
- 时间字段语义明确；
- 数据库变更带 migration；
- 新文件格式带真实样例和解析测试；
- UI 包含 loading/empty/error/stale 状态；
- 离线检查结果没有被表述为硬件验证。

## 需要用户最终确认的架构决策

1. 前端采用 Vue 3 + TypeScript，后端采用 FastAPI；
2. 首版 SQLite，达到明确并发条件后迁移 PostgreSQL；
3. 首版网页完全不提供设备控制；
4. XAFS、XRD 都先新增独立只读快照，不复用危险控制命令作为网页能力；
5. 真实结果格式和 DB/JSON 内容拿到样例后再确认；
6. 平台仅实验室局域网使用，还是未来要允许校外账号访问；
7. 样品编号是否固定使用 `ZJUT-YYYYMMDD-NNN`。
8. 拿到样例后，再确定每个 `.db/.json` 是一次读取、长期只读同步，还是不应接入。

这些决定确认后，再创建代码目录和依赖锁定文件。
